# 月度详情「周度框」纵向形态调研

调研日期：2026-10-25  
新增约束：月度分配已经是底部的横向月份列；周度框如果继续做横向列/带，会和月度、目标画布形成“三横”对撑，视觉上重复。  
目标：换一种方向和组织方式，让周度区域既不使用框框，也不和月度列同构。

---

## 1. 为什么现在的周日历带仍然不对

- 它虽然去掉了卡片框，但仍然是**底部横向一排周段**。
- 月度分配是底部横向月份列，目标画布是横向树；再来一条横向周带，形成三条横向结构对撑。
- 视觉上仍然像“第二排列”，只是把边框换成了刻度。
- 月度详情右侧本来有大块空白，底部再加一条带，空间分配也不高级。

**结论：周度不应继续占用底部横向空间，应该换一个轴向。**

---

## 2. 新原则：月横向、周纵向

- **月度分配**：底部横向列，表达“任务属于哪个月”。
- **目标画布**：横向树，表达“目标如何分解”。
- **周度分配**：放在月度详情右侧，做**纵向周尺**，表达“这个月内任务落在哪一周”。

这样构图从“三条横带”变成“L 形”：

```
┌──────────────────────────────┬──────────┐
│ 目标画布（横向树）            │ 月度详情 │
│                              │ 树画布   │
│                              │   周尺   │
├──────────────────────────────┤          │
│ 月度分配（横向月份列）        │          │
└──────────────────────────────┴──────────┘
```

周度从“底部第二条横带”变成“详情右侧的纵向标尺”，不再和月度对撑。

---

## 3. 候选形态

### 3.1 纵向周尺（Week Ruler）——推荐

在月度详情右侧放一条纵向时间轴：

```
周度
│
● 第1周   10/4–10/10
│         0项
│
● 第2周   10/11–10/17
│         6项 · 20h
│         ● 定制材料的模型构建
│         ● 现成设备的选型  +4
│
● 第3周   本周
│         6项 · 16h
│         ● 新任务1  +6
│
● 第4周   10/25–10/31
│         0项
│         ＋ 拖入
```

- 只有一条竖线、周节点、周标签、任务文字；没有卡片、没有框。
- 当前周节点实心 accent，标签写“本周”；过去周降低透明度。
- 任务以“色点 + 文字”直接挂在节点右侧，最多 2 条 + `+N`。
- 负载写在周标签下方：`6项 · 20h`；可以在节点旁加一条 2px 竖负载线。
- 点击周节点/整行 → 周规划；拖任务到周节点 → 写 `assignW`。
- 拖拽反馈：节点变大/变实、竖线该段变 accent，不出现框。
- 空周：只在 hover 时显示淡 `＋ 拖入`，没有虚线框。

优点：

- 轴向与月度、目标画布都不同，彻底避免对撑。
- 利用月度详情右侧原本空着的区域。
- 纵向空间足够展示 4–6 周、任务名和负载。
- 飞书甘特图的侧轴/任务列语言，克制、高级。
- 没有框，只有线和节点。

缺点：

- 会占用详情画布右侧宽度；窄屏需要折叠。
- 任务多时需要 `+N` 或 hover 浮层。

### 3.2 周环/周弧（Week Dial）

在详情右下角放一个半圆/环形刻度，4–6 周是弧段，当前周高亮，任务以点表示。

- 优点：非常独特，完全不与横向结构重复；视觉记忆点强。
- 缺点：弧段可读性和拖拽命中都不如直线；任务名难以承载。
- 适配度：中，适合做“周负载环”而不是主交互。

### 3.3 连续日刻度带（Day-scale Ribbon）

一条 28–31 天的连续刻度，不按周分栏；周标签浮在上方，当前周用一段 accent 下划线标出。

- 优点：日粒度最强；没有周列感。
- 缺点：仍然在底部横向，和月度列共享同一轴向；对撑问题只缓解，不彻底。
- 适配度：中。

### 3.4 周聚焦卡（Week Focus）

只显示当前周，左右箭头切换周；周负载和任务在一个聚焦区域里。

- 优点：极简、无框、聚焦。
- 缺点：失去 4 周全览；排周时看不到其他周负载。
- 适配度：低。

### 3.5 周热条（Heat Strip）

一条连续条带，按周用颜色深浅表示负载，没有任务名。

- 优点：最轻、无框。
- 缺点：信息太少，无法拖任务；只能做概览。
- 适配度：低。

---

## 4. 推荐：纵向周尺

### 4.1 布局

- 月度详情右侧增加一列 `.mv-weekruler`，宽度 `clamp(150px, 20%, 220px)`。
- 左侧树画布占剩余宽度；KPI 胶囊移到树画布左上角，或收进周尺标题行。
- 周尺与树画布之间只留一条 1px 竖线，不画外框。
- 周尺内部：顶部“周度”标签 + 4–6 个周节点，纵向排列，可滚动。
- 当前周节点在可视区域内自动定位。

### 4.2 视觉

- 竖线：1px `--bd-line`；当前周段竖线 accent 2px。
- 节点：7px 圆点；过去周空心/低透明，当前周实心 accent，未来周空心。
- 周标签：11.5px/600；日期 9px；负载 9px。
- 任务文字：10px，色点 5px，最多 2 条 + `+N`；不套芯片。
- 当前周：“本周”用 accent 文字，不加徽章框。
- 空周：hover 才显示 `＋ 拖入`，没有虚线框。

### 4.3 交互

1. 点击周节点/整行 → 周规划。
2. 拖月度任务到周节点/周行 → 写 `assignW`；节点实心、竖线 accent、幽灵 `→ 第2周`。
3. 悬停周行 → 显示该周完整任务浮层（最多 6 条）。
4. 任务文字点击 → 定位到该周/该任务。
5. 当前周自动滚动到可见位置。

### 4.4 响应式

- 1600 宽详情约 777px：周尺 180px，树画布 597px。
- 2560 宽详情约 1260px：周尺 220px，树画布 1040px。
- 1280 宽详情约 617px：周尺 150px，树画布 467px；树可平移。
- 低于 1180px：周尺折叠成 36px 的竖向点轨，hover/点击展开浮层。
- 更窄时：周尺变成详情顶部的一条紧凑竖向分段控件，或收进抽屉。

---

## 5. 为什么它比底部周带更高级

- 打破三条横向结构，构图从“三横”变成“L 形”。
- 周度成为“标尺”，不是“第二排列”。
- 没有框，只有线、节点、文字。
- 利用详情右侧空白，而不是继续在底部叠加。
- 纵向周尺天然适合 4–6 周、任务名和负载的纵向阅读。
- 飞书甘特图的侧轴/任务列语言，克制、专业。

---

## 6. 落地建议

### P0

- 月度详情改为“树画布 + 右侧纵向周尺”两列。
- 周尺：竖线、周节点、周标签、日期、任务文字、负载；无框。
- 当前周 accent 节点/竖线；过去周低透明。
- 点击周行进周规划；拖任务入周行写 `assignW`。
- 移除底部周日历带和 `padBottom` 预留。
- KPI 胶囊移到树画布左上角或周尺标题行。

### P1

- 周尺折叠为 36px 点轨（窄屏）。
- 任务文字跨周拖动改周。
- 周行 hover 浮层显示完整任务。
- 当前周自动定位。

### P2

- 周负载环/弧作为周尺顶部的小型概览。
- 周/日尺度切换。
- 与周规划页的飞移动画适配“周节点 → 周条”。

---

## 7. 验证重点

- 1600×1000：右侧周尺 4–6 周完整可见，树画布不被压得太窄。
- 1280×720：周尺可折叠；树仍可平移。
- 2560×1300：周尺与树画布比例舒适，不再有底部第三条横带。
- 拖任务入周行：节点/竖线高亮，无框。
- 点击周行：周规划打开，飞移动画不跳。
- 当前周/过去周/空周状态清楚。
- 全程没有卡片、没有圆角框、没有底部横向周带。
