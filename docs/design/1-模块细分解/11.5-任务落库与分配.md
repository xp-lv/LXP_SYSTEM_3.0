# 11.5 · 任务落库与分配 · 全定义

> 父模块：[AI 规划模块](./11-AI规划模块.md) · 状态：〔已定义·待实现〕

**是什么**：把用户已确认的方案翻译成一次**原子批量变更**，经模块 7 变更服务写入任务树、
完成月/周/日分配与完成态。它是 AI 模块唯一允许触碰任务数据的出口。

**为什么**：LLM 直接改数据不可控；逐条调用又会留下几十步 undo 和半落库风险。
必须“全量校验 → 一次快照 → 批量执行 → 失败回滚 → 一步 undo”。

## 输入 `PlanApplication`

```json
{
  "runId": "run-20261025-001",
  "tree": { "mode": "create", "domainId": 3, "title": "CET-6 备考" },
  "operations": [
    { "op": "create_node", "parentRef": "root", "tempId": "n1", "title": "词汇", "lvl": "top" },
    { "op": "create_node", "parentRef": "n1", "tempId": "n2", "title": "核心词书第一轮", "lvl": "top" },
    { "op": "assign_month", "nodeRef": "n2", "month": "2026-11" },
    { "op": "create_node", "parentRef": "n2", "tempId": "n3", "title": "Unit 1-10 精学", "hours": 12, "lvl": "month" },
    { "op": "assign_week", "nodeRef": "n3", "week": "2026-11-04" },
    { "op": "assign_day", "nodeRef": "n3", "day": "2026-11-06" },
    { "op": "complete_node", "nodeRef": 101 }
  ]
}
```

- `nodeRef` 可以是已有节点的真实 id，也可以是本次方案里的 `tempId`；
- `parentRef` 同理；`root` 表示新树的根；
- `mode: "existing"` 表示在现有树内追加/调整，必须带真实 `treeId`。

## 操作类型

| op | 语义 | 约束 |
|---|---|---|
| `create_tree` | 新建目标树并挂到领域 | 受 R39 树上限（当前实现 6 坑，见 01.3） |
| `create_node` | 在父节点下创建子任务 | 父节点存在且允许分解；层级合规 |
| `rename_node` | 改名 | 节点存在 |
| `set_hours` | 改叶子工时 | 仅叶子；≥0 |
| `assign_month` | 落月 | 仅顶层叶子；一个任务一月（R5/R6） |
| `assign_week` | 落周 | 级联补齐月（R10） |
| `assign_day` | 落日 | 必须有工时（R12）；级联补齐周/月（R14） |
| `complete_node` | 标记完成 | 仅叶子；显式确认（R49） |
| `remove_node` | 删除子树 | 二次确认（R49） |
| `create_temp` | 新建临时任务（可选） | v1 默认不开放 |

## 执行顺序（不可乱）

```
1. 解析 refs（真实 id / tempId）→ 得到目标节点集合
2. 全量校验（存在性、类型、层级、规则、容量、引用完整性）
3. 记录一次 undo 快照（整树 + temps）
4. 创建树/领域
5. 创建节点（按父先子后顺序）
6. 改名 / 改工时
7. 落月 → 落周 → 落日（按级联顺序）
8. 完成 / 删除（如用户确认）
9. derive 重算 → 视图重建 → 存档
10. 写 planRun（appliedNodeIds、摘要、文档版本、时间）
```

- 任一步失败 → 恢复到第 3 步快照，整批零残留；`planRun.status='apply_failed'`。
- 成功 → 整批只产生**一步 undo**；`Ctrl+Z` 回到应用前。
- 应用过程中禁用重复点击；多设备下用 `baseVersion` 检测任务数据是否已变化。

## id 与追溯

- 新建节点由全局 `allocId()` 分配真实 id；方案里的 `tempId` 只在批内有效。
- `planRun.appliedNodeIds` 记录本次创建/更新的全部节点 id；
- 文档通过 `runId + docType + version` 可反查任务批次；
- 节点级 `docRef`（文档路径 + 锚点）为 ⚖️ 后续项，v1 不做。

## 与现有服务映射（实现时）

| 方案操作 | 现有原语 |
|---|---|
| 创建目标树 | `world.plantTree(domain, title)`（受 R39 树上限） |
| 创建节点 | `mutations.addSubtask(parent, {title, hours, lvl})` |
| 改名 | `mutations.renameNode(node, title)` |
| 改工时 | `mutations.updateTask(node, {hours})` |
| 落月/落周/落日 | `mutations.assignPeriod(node, 'm' / 'w' / 'd', key)` |
| 移出/换月 | `mutations.unassignPeriod` / `unassignFromMonthDeep` |
| 完成 | `mutations.updateTask(node, {progress:1})` |
| 删除 | `mutations.removeNode(node)` |
| 批量事务 | `mutations.snapshot()` + 新增 `beginBatch/endBatch`（一次快照，内部原语不再重复入栈） |
| 读取上下文 | `queries.*` / `world.getTrees()` / `calendar.today()` / `data.caps` |
| 撤销 | `mutations.undo()`（整批一步回退） |

> `beginBatch/endBatch` 是为 AI 落库新增的小改造：现有原语每次调用都会压一次 undo 快照；
> 批量执行时只在开始压一次，内部调用跳过入栈。校验失败或异常时恢复该快照。

## 分配规则（复用既有语义）

- 落月：`assignM=key`；
- 落周：`assignW=key` 且 `assignM=key.slice(0,7)`；
- 落日：`assignD=key`，`assignW=weekKeyOf(day)`，`assignM=week.slice(0,7)`；
- 换月：按 R8 清理旧子树/分配/补点；
- 逾期补点：不改原 `assignD`，写 `makeup`（R17）；
- 容量：超载只告警不阻断（R24/R56）。

**承接**：R41/R45/R46/R47/R49/R55/R56 · A13 · T26。

**验收**
- 应用后计划树/周视图/3D 世界与文档一致〔手/自〕；
- 一次 undo 完整回退整批〔自〕；
- 任一操作失败零残留、无半写〔自〕；
- 非法 refs / 层级 / 0h 落日 / 超树上限被阻断〔自〕；
- 应用记录可查看：文档版本、节点 id、时间、摘要〔手〕。

**边界**：不生成方案、不写文档、不绕过变更服务；不自动删除/完成。
**待定**：单批节点上限（建议 200）；是否允许部分应用；应用失败后的重试策略。
