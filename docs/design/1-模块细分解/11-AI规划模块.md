# 11 · AI 规划模块 · 完全定义

> 《0-模块分解》模块 11。把“靠直觉分解任务”升级为“对话澄清 → 系统化分解 → 文档链 → 用户确认 → 经变更服务落库”的规划闭环。
> 状态：〔已定义 · 待实现〕；标注 ⚖️ 的为待拍板项。

## 定义与边界

- **定义**：一个与人协作的规划顾问。它从顶层目标出发，通过多轮对话澄清需求，
  按系统化方法（结果导向 WBS / MECE / 依赖与关键路径 / 工时与容量校验）生成递进式
  Markdown 文档链；用户确认后，把文档中的方案经**模块 7 变更服务**落成任务树、
  月份/周/日排期与完成态。
- **边界**：
  - **不直接写任务数据**：不碰 localStorage、data.json、节点对象；一切任务写入经 `mutations`（红线）。
  - **不替用户做取舍**：AI 给候选方案、依据、风险与假设；目标优先级、范围裁剪、最终确认由用户决定。
  - **不自动执行**：v1 只做用户发起的规划会话；不做后台定时 agent、不做无人值守落库。
  - **不拥有日历/任务模型**：只读 `queries` / `calendar` / `data.caps`，写只经变更服务。
  - **不写受管目录之外的文件**；文档仅 `.md`，路径必须在 AI 文档根内。
  - **不删除**：AI 不自动删树/删任务/撤回完成；这些动作必须显式确认。
  - **不做通用聊天**：会话以目标分解为任务导向；闲聊不产生文档与落库。

## 核心流程

```
目标对话 → 需求契约 → 现状/约束 → 分解结构 → 任务清单 → 排期/执行
        → 预览与规则校验 → 用户确认 → 批量落库（一步 undo） → 执行复盘
```

**示例**：用户说“我想 6 个月通过 CET-6” → AI 追问当前水平/每周投入/硬期限 →
生成目标契约与现状文档 → 按结果域拆成词汇/阅读/听力/写作/口语 →
每个结果域拆到 0.5–8h 的原子任务并标验收标准 → 汇总工时与容量 →
生成任务清单与月/周排期 → 用户逐篇查看/修改 → 确认应用 →
一次事务写入任务树（可一步撤销）→ 执行后 AI 读进度生成复盘。

## 最小功能模块

### 对话与需求澄清
- 多轮对话，把模糊目标转成结构化 `DecompositionBrief`；
- 优先追问高影响信息：成功标准、截止时间、每周可用工时、现状、约束、非目标；
- 用户可回答“不知道”，AI 必须把推断写成**显式假设**，不得伪装成事实；
- 会话可中断、重试、恢复；历史保留最近 N 轮 + 摘要。

### 系统化分解
- 用结果导向 WBS 而不是按时间/工具拍脑袋：
  - L0 目标 → L1 结果域（3–5 个，尽量 MECE）→ L2 交付物/里程碑 → L3 原子任务；
  - 原子任务粒度 0.5–8h；>8h 继续拆，<0.5h 合并；
  - 每个叶子必须有**可验收的完成标准**；
  - 标注依赖、关键路径、风险与缓冲；
- 映射到系统约束：顶层画布 3 级封底（R2）、周度 2 级（R3）、
  一个任务一月（R6）、落日必须有时长（R12）；
- 工时汇总后与可用容量比对，超载时给“扩期/缩范围/加缓冲”的候选，而不是硬排。

### 文档链生成
- 固定递进链：目标契约 → 现状与约束 → 分解结构 → 任务清单 → 排期与执行 → 决策记录；
- 每篇有最小字段、frontmatter、版本号；后篇引用前篇版本；
- 上游变更使下游草稿 `stale`，未重新确认不得落库；
- 文档存入受管目录 `{DATA_DIR}/agent-docs/{goal-slug}/`，可按目标浏览；
- 文档可在“AI 规划”视图内查看、批注、重新生成。

### 方案评审与确认
- 预览分解树、变更摘要、规则校验结果、容量告警、文档链接；
- 支持“通过 / 要求修改 / 放弃”；
- 任务落库必须用户显式确认；删除/完成类操作额外确认；
- 未确认、`stale`、规则错误 → 禁止落库。

### 任务落库与分配
- 把已确认方案翻译成变更操作：建树、建节点、改名、改工时、落月/周/日、完成、删除；
- 全量校验 → 一次快照 → 批量执行 → 派生 → 呈现 → 存档；
- 任一操作失败整批回滚；整批只产生一步 undo；
- 记录 `planRun.appliedNodeIds`，建立文档与任务的批次级追溯。

### 上下文构建
- 只读读取领域/树/任务/日历/容量/文档索引；
- 给模型的是受控摘要与工具，不是全量任务树；按需
  `get_tree` / `search_tasks` / `get_workload` / `list_docs` / `read_doc`；
- 每次规划回合前刷新上下文；任务树变化时提示“上下文已变化”；
- 不把 token、localStorage、无关文档发给模型。

### 模型接入与安全
- 服务端代理 OpenAI 兼容接口，API Key 只在环境变量；
- 支持原生工具调用；不支持时降级为严格 JSON 动作协议；
- 流式输出、超时、重试、限流、token/轮次上限；
- 文档路径校验、Markdown 清洗、prompt injection 防护、日志脱敏。

## 系统化分解方法（模块内置契约）

> 这是本模块与“让模型随便拆一下”的根本区别：分解必须过检查，而不是看起来合理。
> 完整方法、检查项与反模式见 [11.2 系统化分解](./11.2-系统化分解.md)。

1. **目标可判定化**：把“学好英语”改成“2027-06 前通过 CET-6，总分 ≥425，每周投入 10h”。
2. **结果域划分**：按“要交付什么结果”切，不按“先学什么后学什么”切；
   结果域 3–5 个，尽量相互独立、合起来覆盖目标（MECE）。
3. **交付物/里程碑**：每个结果域至少一个可验收交付物；里程碑是“可检查的状态”，不是日期别名。
4. **原子任务**：动词 + 对象 + 完成标准；0.5–8h；一个任务只落一个月；需要跨周就拆。
5. **依赖与关键路径**：标 `dependsOn`；禁止循环依赖；关键路径上的任务优先排期。
6. **工时与容量**：叶子工时自底向上汇总；与 `caps`（工作日/周末）和可用周数比对；
   超载必须显式告警。
7. **缓冲与风险**：为估算误差、外部依赖、复盘留 15–25% 缓冲；
   风险写入现状/约束与决策记录。
8. **覆盖检查**：每个成功标准至少被一个结果域覆盖；每个结果域至少有一个任务；
   没有“孤儿任务”。
9. **反模式拦截**：
   - 按季度/月份切任务，而不是按结果切；
   - 把“学习/调研/思考”当任务，没有交付物；
   - 任务粒度过大（“完成项目”）或过细（“打开文档”）；
   - 只列任务，不列依赖、验收标准、缓冲；
   - 用 AI 的推断替代用户的范围取舍。

**人机分工**：AI 负责提问、结构化、生成候选、校验、文档化；
用户负责目标取舍、优先级、约束、最终确认。AI 不替用户“拍板”。

## 自动行为（承接《3》A11–A15）

- **A11 上下文刷新**：每次规划回合前读取最新任务树/日历/容量；与上次快照不同则提示。
- **A12 文档版本化**：生成/编辑后原子写入；上游变更 → 下游 `stale`。
- **A13 落库传播**：确认 → 校验 → 批量变更 → 派生 → 3D/视图 → 存档；整批一步 undo。
- **A14 失败恢复**：模型超时/限流/工具异常 → 保留草稿、可重试、不落库。
- **A15 成本保护**：token/工具轮次超限 → 暂停并提示缩小范围。

## 时序（承接《4》）

- **T24 AI 对话回合**：发送 → 上下文快照 → 模型 → 工具调用/结果回填 → 最终回复 → 会话落盘。
- **T25 文档链生成**：目标契约 → 现状/约束 → 分解结构 → 任务清单 → 排期/执行；
  后篇引用前篇版本。
- **T26 方案评审与落库**：预览 → 确认 → 全量校验 → 批量变更（快照）→ 派生 → 呈现 → 存档；
  失败回滚。
- **T27 上下文刷新**：每回合前读取最新任务树/容量；变化则提示。
- **T28 失败恢复**：超时/限流/工具失败 → 保留草稿 → 可重试；不落库。
- **T29 执行复盘循环**：落库 → 执行 → 读进度 → 复盘文档 → 调整建议 → 再次确认落库。

## 规则（承接《5》R41–R57）

R41（不直写任务数据）· R42（未确认不落库）· R43（文档链顺序/stale）·
R44（文档最小字段）· R45（遵守既有任务规则）· R46（真实 node id）·
R47（批量事务/一步 undo/回滚）· R48（变更摘要）· R49（不自动删除/完成）·
R50（文档路径与原子写）· R51（不可信内容/Markdown 清洗）· R52（Key 只在服务端）·
R53（失败不半落库）· R54（token/轮次上限）· R55（planRun 追溯）·
R56（容量告警）· R57（文档/任务解耦的生命周期）。

## 数据（承接《6》§I）

- 任务存档 schema 不新增必填字段；AI 不改变任务树核心结构。
- 服务端受管目录：
  - `{DATA_DIR}/agent-docs/{goal-slug}/`：用户可浏览的 MD 文档链；
  - `{DATA_DIR}/agent-runs/{runId}.json`：运行记录（状态、文档版本、应用节点、摘要）；
  - `{DATA_DIR}/agent-chats/{conversationId}.json`：会话记录。
- 文档 frontmatter 带 `runId / docType / order / treeId / status / version`；
- 文档与任务解耦：删文档不删任务，删树不自动删文档（run 标记 orphaned）。
- 可选 `docRef`（节点级文档引用）为 ⚖️ 后续项；v1 用 `planRun.appliedNodeIds` 做批次级追溯。

## 验收（承接《7》C11）

- 多轮对话可澄清、可中断、可恢复〔手〕；
- 文档链按顺序生成、可查看、上游变更下游 stale〔手/自〕；
- 未确认 / stale / 规则错误 → 零落库〔自〕；
- 确认后任务树/月/周/日与文档一致〔自/手〕；
- 一次落库=一步 undo；失败整批回滚、无半写〔自〕；
- 文档路径穿越/非 md/超大文件被拒绝〔自〕；
- Markdown 原始 HTML 不执行〔自〕；
- API Key 不出现在前端、响应、日志〔自〕；
- 模型超时/不可用有提示且不丢草稿〔手〕；
- 容量超载在文档与预览中显式标红〔手〕。

## 落地顺序（建议）

1. **安全与存储**：修静态目录暴露；建受管目录 + 文档/运行/会话 API；路径与鉴权测试。
2. **文档查看器**：目录树 + Markdown 预览 + 版本/状态；先不接模型也能用。
3. **模型接入**：服务端 LLM 代理 + 对话 UI + 流式/重试/限流。
4. **规划闭环**：上下文构建 → 需求契约 → 系统化分解 → 文档链 → 方案预览。
5. **落库事务**：`beginBatch/endBatch` + 校验 + 回滚 + 一步 undo + planRun。
6. **复盘与打磨**：执行复盘、容量告警、prompt 调优、验收走查。

> 阶段 1–2 不依赖 LLM，可先独立上线；阶段 3 之后才需要模型凭证与费用预算。

## 待定 ⚖️

- 文档链是“逐篇确认”还是“整链一次确认”（建议默认逐篇可跳过，落库前整链确认）；
- 模型提供方与是否支持原生 tool calling（决定 JSON 降级协议）；
- 流式输出是否作为 v1 必需（建议是，体验差异大）；
- 节点级 `docRef` 是否进入 v1（建议 v2）；
- 文档/运行记录的保留期与“删除 run 是否连带删文档”；
- 多设备同时编辑同一 run 的锁策略（建议：单写者 + `baseVersion` 冲突提示）；
- 是否允许 AI 创建领域/临时任务（v1 建议只创建目标树与任务，不建领域）。

## 模块关系（《2》）

- **AI—数据**：读 `queries` / `world`，写只经 `mutations`；这是唯一的任务写通道。
- **AI—顶层**：读顶层结构；落库时创建/改名/落月。
- **AI—周度**：读周/日负载；落库时落周/落日/改工时。
- **AI—今日**：读执行与完成态；用户确认后可完成指定任务。
- **AI—岛屿**：读领域/树列表；经世界管理创建目标树（受 R39 上限）。
- **AI—树/星球/环境**：无直接交互；所有呈现由数据传播链间接更新。
- **AI—交互/信息**：AI 有自己的全屏视图与文档查看器，不复用 3D 拾取/信息面板；
  入口走横向“视图路由”。
- **AI—外部**：LLM 服务与文档存储是模块外部依赖，不进入任务数据模型。
