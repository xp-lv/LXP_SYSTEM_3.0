# 11.6 · 上下文构建 · 全定义

> 父模块：[AI 规划模块](./11-AI规划模块.md) · 状态：〔已定义·待实现〕

**是什么**：在每次 AI 规划回合前，从任务树、日历、容量、文档中构建一份**准确、受控、可追溯**
的上下文，供模型做分析与分解。

**为什么**：把全量任务树塞给模型既贵又容易漂移；上下文必须按需读取、可校验、能发现过期。

## 上下文来源

| 来源 | 读什么 | 用途 |
|---|---|---|
| `world` | 领域、树列表、激活树 | 让 AI 知道在哪个目标上工作 |
| `queries` | 叶子、月负载、周任务、日事项、逾期 | 现状、断梢、负载、进度 |
| `calendar` | `today()`、月/周键、周区间 | 排期键与周归属 |
| `data.caps` | 工作日/周末容量 | 容量校验 |
| `persistence/exportDoc` | 树结构快照（只读） | 生成 `get_tree` 结果 |
| 文档索引 | 文档路径、docType、状态、版本 | 让 AI 读取已有规划，不重复造轮子 |

## 初始上下文（每回合）

- 当前激活领域/树的摘要；
- 每棵树的：标题、叶子数、完成率、断梢数、逾期数、最近分配月份；
- 当前树的浅层大纲（默认深度 2；节点多时截断并标注）；
- 今日/本周/本月的负载与容量；
- 当前 run 的文档链索引与状态；
- 用户选定的上下文范围（当前树 / 新目标 / 全部树摘要）。

**不发送**：token、localStorage 原文、无关文档全文、其他用户的私有内容（单用户场景也遵循最小必要）。

## 只读工具

| 工具 | 返回 | 限制 |
|---|---|---|
| `get_task_overview` | 领域/树摘要 + 统计 | ≤ 当前树上限（TREE_CAP） |
| `get_tree` | 指定树节点树（id/title/lvl/hours/assign/progress） | 默认深度 2，可请求更深；单次 ≤500 节点 |
| `search_tasks` | 按标题/状态/分配检索 | ≤50 条 |
| `get_workload` | 月/周/日负载与容量 | 指定范围 |
| `list_docs` | 文档树 + 状态/版本 | 当前 run 或全部 |
| `read_doc` | 单篇 Markdown | ≤256KB；可按章节截断 |

- 工具只读，不产生写操作。
- 工具结果在会话中保留摘要；原始大 payload 不重复注入下一轮。
- 工具调用参数必须校验（id 存在、范围合法、日期格式）。

## 上下文预算

- 单次请求目标 ≤32k tokens（⚖️ 按模型调整）；
- 初始上下文与历史消息合计超限时，优先保留：
  1. 需求契约与假设；
  2. 当前树摘要；
  3. 最近 2 轮对话；
  4. 文档索引（不放大段正文）；
- 超限时提示用户缩小范围，而不是静默截断关键约束。

## 过期检测

- 每次规划回合读取任务树的版本（如 `savedAt` 或结构摘要 hash）；
- 与上次快照不同 → 在 UI 提示“任务树已变化，是否重新分析？”；
- 落库前再次校验：若树/分配在预览后被修改，阻断或要求刷新预览；
- 文档上游版本变化 → 相关下游标记 `stale`（11.3）。

**承接**：AI2/AI5 · R41/R54 · T27/A11。

**验收**
- 上下文与当前任务树一致（抽样核对）〔自/手〕；
- 任务树变化能被检测并提示〔自〕；
- 单次请求不超预算；超限有降级策略〔自〕；
- 工具参数非法被拒绝，不产生越权读取〔自〕。

**边界**：不做写操作；不缓存敏感内容到前端日志；不把上下文当作指令执行。
**待定**：树结构 hash 算法；上下文分层缓存；是否允许用户手动勾选“把某篇文档加入上下文”。
