# 11.1 · 对话与需求澄清 · 全定义

> 父模块：[AI 规划模块](./11-AI规划模块.md) · 状态：〔已定义·待实现〕

**是什么**：把用户的一句模糊目标，通过多轮对话收敛成可执行的结构化需求契约 `DecompositionBrief`。

**为什么**：分解质量的上限由需求澄清决定。不问清截止时间、可用工时、成功标准、非目标，
后面的分解再漂亮也是空中楼阁。

**行为**
- 开场先读上下文（当前树/容量/已有文档），让用户选择“分析现有目标”或“新目标”。
- 追问按影响排序，每轮最多 3 个问题：
  1. **成功标准**：怎样算完成？可观察、可度量、由谁验收？
  2. **截止时间与投入**：硬期限是什么？每周几小时、哪些天可用？
  3. **现状与资源**：已经有什么、缺什么、依赖谁、可调用什么工具/人？
  4. **约束与非目标**：不能做什么？明确不做什么（防止范围蔓延）？
  5. **优先级与风险偏好**：质量/速度/范围如何取舍？能接受多大不确定性？
- 每个问题尽量给选项，并提供“不确定 / 让你假设”，降低用户回答成本。
- 用户不确定时，AI 必须把推断写成**显式假设**，在文档、预览、决策记录中标注；
  不得把假设说成事实。
- 每轮结束回述“我理解的目标 / 约束 / 假设”，请用户确认或纠正。
- 会话可中断、重试、刷新恢复；保留最近 N 轮 + 摘要，避免上下文爆炸。

**输出 `DecompositionBrief`**
```
{
  goal, successCriteria[], deadline, availableHoursPerWeek,
  availableDays[], currentState, resources[], constraints[],
  nonGoals[], priorities[], riskTolerance, assumptions[], openQuestions[]
}
```

**承接**：AI2–AI5 · R42/R44/R53/R54 · T24/T27。

**验收**
- 关键字段完整，或缺失项有显式假设〔手〕；
- 用户确认过的目标/约束与回述一致〔手〕；
- 刷新后可恢复会话与 brief〔手〕；
- 未确认 brief 不进入系统化分解〔自〕。

**边界**：不写任务、不生成最终文档、不替用户决定范围。
**待定**：追问是“一次三问”还是“逐项表单”；会话保留轮数；是否允许语音输入。
