# 11.3 · 文档链生成 · 全定义

> 父模块：[AI 规划模块](./11-AI规划模块.md) · 状态：〔已定义·待实现〕

**是什么**：把分解过程写成一组**逻辑递进**的 Markdown 文档，按固定顺序组织在受管文件夹中，
让用户能读、能批注、能追溯“为什么这样拆”，并在确认后作为落库依据。

**为什么**：只给一棵任务树，用户无法审查 AI 的假设与推理；文档链把“结论”展开成
“目标 → 现状 → 结构 → 任务 → 排期”的可审查过程，避免黑箱。

## 文档链（固定顺序）

| 顺序 | 文件 | 作用 | 最小字段 |
|---|---|---|---|
| 00 | `00-目标契约.md` | 确认“做什么、为什么、怎样算成功” | 目标、成功标准、期限、投入、约束、非目标、假设 |
| 01 | `01-现状与约束.md` | 确认“从哪里出发、缺什么、风险在哪” | 现状、差距、资源、依赖、风险、容量 |
| 02 | `02-分解结构.md` | 确认“为什么这样切” | 结果域、MECE 检查、覆盖矩阵、依赖图、粒度规则 |
| 03 | `03-任务清单.md` | 确认“具体做什么” | 叶子任务、工时、验收标准、依赖、建议月份 |
| 04 | `04-排期与执行.md` | 确认“怎么排、怎么复盘” | 月/周/日分配、容量、里程碑、缓冲、复盘节奏 |
| 99 | `99-决策记录.md` | 记录“用户改了什么、AI 假设了什么” | 决策、理由、假设、变更、未决问题 |

- 后篇必须引用前篇的**版本号**；前篇变更 → 后篇标记 `stale`，未重新确认不得落库。
- 文档之间用相对链接串联，形成可点击的阅读链。
- 每篇文档末尾带“上一篇 / 下一篇”导航和“本文件依赖的假设”清单。

## 文件夹组织

```
{DATA_DIR}/agent-docs/
  cet6/
    00-目标契约.md
    01-现状与约束.md
    02-分解结构.md
    03-任务清单.md
    04-排期与执行.md
    99-决策记录.md
  fitness/
    ...
```

- 文件夹名由目标生成 `goal-slug`（小写、短横线、去特殊字符）；冲突时加 `-2`、`-3`。
- 同一目标的多轮 run 可复用文件夹并递增版本，或新建 `cet6-2/`；由用户在评审时选择。
- 文档根目录由服务端配置，禁止写到根外；仅允许 `.md`。

## frontmatter

```yaml
---
runId: run-20261025-001
docType: goal-contract        # goal-contract | current-state | decomposition | task-list | schedule | decision-log
order: 0
treeId: 42
goal: 6 个月内通过 CET-6
status: draft                 # draft | reviewed | approved | stale
version: 3
upstream: []                  # 依赖的前篇 docType + version
updatedAt: 2026-10-25T10:00:00+08:00
---
```

## 生成与版本

- AI 按顺序生成；默认**逐篇可审**，用户可跳过审阅但落库前必须整链确认。
- 用户对某篇提出修改意见 → 只重写该篇，版本 +1；下游自动 `stale`。
- 用户直接编辑文档 → 保存为新版本；AI 后续生成必须读取最新版本。
- 所有写入原子化（临时文件 + rename）；写入前校验路径、扩展名、大小、版本。

## 查看器

- 左侧目录树：文件夹 / 文档 / 状态徽标（draft/reviewed/approved/stale）/ 版本。
- 右侧 Markdown 预览：标题、表格、代码块、链接、任务清单样式。
- 支持“源码 / 预览”切换；编辑保存前提示下游将 stale。
- 文档内链接可跳转；`treeId` 可提供“定位到树”按钮（可选）。
- 渲染必须禁用原始 HTML 或严格清洗（R51）。

**承接**：AI6–AI9 · R43/R44/R50/R51 · T25/A12。

**验收**
- 六篇文档按顺序生成，最小字段齐全〔自/手〕；
- 后篇引用前篇版本；前篇修改后后篇状态变 `stale`〔自〕；
- 文档只出现在受管目录，路径穿越/非 md/超大文件被拒〔自〕；
- 文档可查看、可编辑、可重新生成〔手〕；
- 删除文档不删除已落库任务〔自〕。

**边界**：不直接写任务；不生成非 Markdown 文件；不做通用网盘。
**待定**：文件夹复用 vs 每次 run 新建；是否支持导出 zip；文档内是否嵌入任务预览。
