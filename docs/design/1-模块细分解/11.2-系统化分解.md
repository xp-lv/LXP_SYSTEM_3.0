# 11.2 · 系统化分解 · 全定义

> 父模块：[AI 规划模块](./11-AI规划模块.md) · 状态：〔已定义·待实现〕

**是什么**：把 `DecompositionBrief` 变成“目标 → 结果域 → 交付物 → 原子任务”的结构化分解，
并过一遍规则、依赖、工时与容量检查。它是本模块与“让模型随便拆一下”的根本区别。

**为什么**：直觉分解的典型问题是：按时间切、按工具切、粒度失控、没有验收标准、
不估工时、不排依赖、不留缓冲。系统化分解把这些都变成可检查项。

## 分解方法

### 1 · 目标可判定化
- 把愿望改写成“结果 + 期限 + 度量”：
  - ✗ “学好英语”
  - ✓ “2027-06 前通过 CET-6，总分 ≥425，每周投入 10h”
- 成功标准必须可观察、可验收；无法判定的标准退回澄清（11.1）。

### 2 · 结果域划分（L1）
- 按“要交付什么结果”切，不按“先学什么后学什么”切；
- 3–5 个结果域，尽量满足：
  - **ME**（相互独立）：两个结果域不重复计同一份工作；
  - **CE**（完全穷尽）：合起来覆盖全部成功标准；
- 每个结果域写一句“完成后世界有什么不同”，避免用动词列表冒充结果域。

### 3 · 交付物 / 里程碑（L2）
- 每个结果域至少一个可验收交付物；
- 里程碑是“可检查的状态”（如“完成 3 套真题且平均分 ≥400”），不是日期别名；
- 交付物尽量可命名、可展示、可验收。

### 4 · 原子任务（L3）
- 结构：动词 + 对象 + 完成标准；
- 粒度 0.5–8h：>8h 继续拆，<0.5h 合并；
- 一个任务只落一个月（R6）；需要跨周就拆成多个任务；
- 每个叶子必须有验收标准，不能只写“学习/调研/思考”；
- 优先产出“交付物型任务”（写完、做完、跑通、提交），而不是“投入型任务”。

### 5 · 依赖与关键路径
- 每个任务可标 `dependsOn`；
- 依赖图必须无环；发现环就拆或改顺序；
- 识别关键路径：最长依赖链决定最短完成时间；
- 关键路径上的任务优先排期，非关键路径可并行或后置。

### 6 · 工时与容量
- 叶子工时自底向上汇总；父级工时=子级汇总（R1/R22）；
- 与 `caps`（工作日/周末）和可用周数比对；
- 超载时给三种候选，而不是硬排：
  1. 扩期（延长截止）；
  2. 缩范围（砍非目标/降标准）；
  3. 加缓冲（减少并行、留复盘）。
- 缓冲建议 15–25%，外部依赖越多越高。

### 7 · 覆盖检查
- 每个成功标准至少被一个结果域覆盖；
- 每个结果域至少有一个任务；
- 没有“孤儿任务”（不属于任何结果域）；
- 没有“幽灵结果域”（没有任何任务支撑）。

### 8 · 反模式拦截
- 按季度/月份切任务，而不是按结果切；
- 把“学习/调研/思考”当任务，没有交付物；
- 任务粒度过大（“完成项目”）或过细（“打开文档”）；
- 只列任务，不列依赖、验收标准、缓冲；
- 用 AI 的推断替代用户的范围取舍；
- 把“每天学 2 小时”当成计划，而不是把结果拆成可验收单元。

## 输出 `DecompositionResult`

```
{
  goal, successCriteria[], constraints[], assumptions[], nonGoals[],
  outcomes: [{
    title, rationale,
    deliverables: [{ title, acceptance }],
    tasks: [{ tempId, parentTempId, title, hours, acceptance, dependsOn[] }]
  }],
  scheduleHints: { suggestedMonths[], suggestedWeeks[], suggestedDays[] },
  checks: {
    mece: { ok, overlaps[], gaps[] },
    depth: { ok, maxDepth },
    granularity: { ok, tooLarge[], tooSmall[] },
    dependencies: { ok, cycles[] },
    capacity: { ok, requiredHours, availableHours, overload[] },
    coverage: { ok, uncoveredCriteria[], orphanTasks[] }
  }
}
```

**承接**：R1/R2/R3/R5/R6/R12/R22/R39/R45 · AI5–AI9。

**验收**
- 每个成功标准有覆盖、每个叶子有验收标准〔自/手〕；
- 依赖图无环；深度与粒度符合系统约束〔自〕；
- 工时汇总与容量比对有结论（通过/超载候选）〔自〕；
- 用户能看懂“为什么这样拆”（结果域 rationale + 假设）〔手〕。

**边界**：不落库、不写文档最终版（由 11.3 负责）、不替用户选优先级。
**待定**：MECE 是启发式检查还是强制阻断；工时估算是否采用三点估算；AI 是否可建议“放弃某个非目标”。
