# 11.4 · 方案评审与确认 · 全定义

> 父模块：[AI 规划模块](./11-AI规划模块.md) · 状态：〔已定义·待实现〕

**是什么**：在文档链与任务落库之间的人机确认闸门。它把“AI 说方案合理”变成
“用户看见变更、看见风险、明确点确认”。

**为什么**：LLM 会自信地编造结构、工时和排期。没有评审闸门，错误会直接进入任务树，
而且很难区分“AI 的假设”与“用户的目标”。

## 预览内容

1. **分解树预览**：只读树形结构（目标 → 结果域 → 交付物 → 任务），可展开/折叠；
   可复用现有分解画布的只读渲染。
2. **变更摘要**：
   - 新建树 / 领域（如有）；
   - 新建节点数、改名数、工时变更数；
   - 落月/落周/落日数量与关键项；
   - 完成/删除数量（高亮，需额外确认）。
3. **规则校验**：
   - 通过 / 警告 / 错误三级；
   - 错误 = 阻断落库（如超过 3 级、非叶子分解、0h 落日、一个月多任务、树超上限）；
   - 警告 = 允许落库但必须看见（如容量超载、无验收标准、依赖环外的弱依赖）。
4. **容量校验**：按 `caps` 与可用周数计算月/周/日负载；超载标红并给候选。
5. **文档链接**：每项变更可回溯到文档章节；文档状态必须为 `approved` 或用户显式跳过。
6. **假设清单**：AI 推断的假设逐条列出，用户可改；改后相关文档与预览重算。

## 确认级别

| 操作 | 确认级别 |
|---|---|
| 写文档 / 改文档 | 自动保存，不需要审批 |
| 创建树/节点、改名、改工时、落月/周/日 | **整批显式确认** |
| 完成 / 撤回完成 | 逐项或整批显式确认 |
| 删除树 / 删除节点 | **二次确认**，并展示影响范围 |
| 放弃方案 | 一键，但保留文档与运行记录 |

- “确认”只能由用户点击或明确指令触发；AI 不得自行确认（R42）。
- 未确认、`stale`、存在阻断级规则错误 → “应用”按钮禁用并说明原因。
- 确认后生成 `planRun`，记录文档版本、变更摘要、应用节点 id、时间（R55）。

## 交互

- “应用方案” → 二次确认弹窗（摘要 + 不可逆提示 + 是否保留文档）→ 执行落库。
- “要求修改” → 回到对话/某篇文档，记录用户意见；可只重生成受影响的文档。
- “放弃” → run 标记 `discarded`；文档保留可查看；不产生任务变更。
- 应用完成后显示“已应用 · 查看变更 · 撤销”入口；撤销=一步 undo（R47）。

**承接**：AI10–AI12/AI14 · R42/R45/R48/R49/R55 · T26。

**验收**
- 未确认 / stale / 阻断错误时，“应用”不可用或后端拒绝〔自/手〕；
- 预览摘要与实际落库操作一致（数量、目标、月/周/日）〔自〕；
- 放弃后任务树零变化〔自〕；
- 应用后一次 undo 可完整回退〔自〕；
- 删除类操作必须二次确认〔手〕。

**边界**：不生成方案（11.1/11.2）；不执行落库（11.5）；不替代用户做范围取舍。
**待定**：整链确认 vs 逐篇确认；是否允许“部分应用”（只应用某个结果域）；预览是否可拖拽调整后再应用。
