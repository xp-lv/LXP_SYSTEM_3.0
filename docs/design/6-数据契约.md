# 6 · 数据契约

> 新系统（单岛 + 领域=数据分组）的**持久化 schema、派生规则、错误路径**。
> 本文档定"数据长什么样"；写入口唯一性见红线。
> 标注：〔已定〕可照此实现 · ⚖️ 待定。

---

## A · 存档根结构（localStorage，键 `lxp_redesign`）

```
存档根 = {
  schema: 2,                              // 版本号（旧 app=1），迁移用
  domains: [ { id, name, color } ],       // 领域=纯数据分组（无坐标无岛）
  trees:   [ 节点… ],                     // 全部树根平铺；每棵根节点带 domainId
  island:  {
    treeSlots: [ { x, z, h, r, treeId } ] // 单岛坑位表（固定六坑：中心+五边形）；treeId=null 为墓碑坑
  },
  active:  { domainId, treeId },          // 激活（替代旧 activeIdx/activeTreeIdx 双下标）
  temps:   [ 临时任务… ],                 // 全局日程池
  caps:    { day, weekend },              // 日容量
  orchard: [ 归档记录… ],                 // 仅存档保留、无 UI（R30 已定）
  exec:    { items:[{nodeId,startedAt,decomposed,page}], collapsed }
                                         // 执行区状态（05.6 v12）——随云同步到服务器 data.json
}
```

- 领域与岛解耦：删领域只动 `domains` 与树的 `domainId`，坑位不动。〔已定〕
- 激活用 **id 引用**（旧版用数组下标，插入删除即错位——废弃）。〔已定〕
- `exec` 为**可选字段**（旧档无此字段 → 空默认），不 bump schema；节点不存在/已完成的
  陈旧项在载入恢复时过滤。

- 存 UI 偏好（提示条关闭记忆等），由 persistence `getPref/setPref` 单拥有读写；
不属于存档根、不参与导出/导入。

存 UI 偏好（提示条关闭记忆等），由 persistence `getPref/setPref` 单拥有读写；

## B · 节点结构（任务树）

```
节点 = {
  id, title,
  parent, children[], depth, leaf,
  hours,                    // 叶子工时（周度域起存在；父级=派生，不存）
  lvl,                      // 'top' | 'month' | 'week'（'temp' 只在日程池）
  order,                    // 今日清单排序
  progress,                 // 0 | 1（二值）
  completedAt,              // 完成时间戳（progress→1 时写入；撤回 progress→0 时清除——防旧戳误判 R28）
  overdue,                  // 逾期标记（派生可重算，持久化仅为扫描性能）
  assignM, assignW, assignD,// 落月/周/日（逾期后冻结为历史锚点）
  makeup,                   // 补点日 'YYYY-MM-DD'（可覆盖/清除）
  checklist,                // 今日草稿分解 [{t,done}]
  domainId                  // 仅树根使用
}
```

```
临时任务 = { id, title, hours, assignD?, makeup?, progress, order, completedAt?, lvl:'temp' }
归档记录 = { id, title, domainId, archivedAt, tree:节点 }
```

- 已废弃字段不得再入档：`planned` / `effort` / `abandoned` / 旧物候键。〔已定〕

## C · 派生字段（不持久化，载入/变更后重算）

| 派生 | 定义 |
|---|---|
| `H` | 子树工时汇总（叶子=hours） |
| `pct` | 完成工时 / 总工时 |
| `bare` | **断梢**：叶子 且 progress<1 且 **无 assignD 且无 assignW**（assignM 不影响——落月是规划层动作，不构成可执行排期；月粒度任务仍需推到周/日才熄灭红光） |
| `buckets` | done/overdue/assigned/floating 工时桶 |
| `redCount` | 子树逾期任务数 |
| `overdue` | 持久字段：由 R16 扫描维护（启动+跨天），derive 不重算 |

## D · id 与关联规则

- **D1** 任务 id 全局单调分配，**起始值为 1**（非 0——JS 中 0 为 falsy，作为 id 会干扰 `if(node.id)` 存在性判断）；载入后回播最大 id 再续发（防重启撞旧档）。〔已定〕
- **D2** 坑位↔树按 `treeId` 关联（禁止数组下标对应）。〔已定〕
- **D3** 树↔领域按 `domainId`；删除领域=**仅空领域可删**（有树拒绝并提示）〔已定〕。

## E · 写入与原子性

- **E1** 一切写入走变更服务（红线）；存档在变更链末尾整包序列化。〔已定〕
- **E2** 写入原子性：序列化成功才调 setItem；setItem 失败（配额满等）旧档不受影响（localStorage 原子语义），返回 notice 告知用户即可。〔已定〕
- **E3** 序列化剔除派生字段（逐字节可 diff，便于测试与迁移）。〔已定〕

## F · 错误路径

| 情形 | 行为 |
|---|---|
| 存档 JSON 解析失败 | 旧档改名备份（`lxp_redesign.bak`）→ 全新初始状态 → 提示"存档损坏已备份" |
| schema 版本高于当前程序 | 拒绝载入并提示升级程序（不猜结构） |
| schema 版本低于当前程序 | **不迁移**（H1 已定），横幅告知"检测到旧版存档已忽略" |
| localStorage 不可用/写满 | 内存模式运行 + 每次变更提示导出 JSON |
| 载入的激活引用失效 | 走激活回退链（A7），存档在下次写入时被修正 |

## G · Undo 快照结构

- **G1** 快照=**整树深拷贝**（含 makeup/order/checklist）+ 所属 treeId + 操作摘要。〔已定·沿用旧实现〕
- **G2** 整树快照（当前量级 <百节点/树，内存开销可忽略）；op-log 是后续优化方向，非决策。〔已定〕
- **G3** undo 栈深上限 **50 步**（到达后丢弃最旧快照）。〔已定〕

## H · 迁移（旧 app schema v1 → v2）

- **H1** 已定：**不提供 v1→v2 迁移**（新键名独立，旧档不动）；检测到旧档时经横幅告知。
- **H2** 导出格式=存档根本身（含 schema 版本）；导入校验失败整体拒绝。〔已定〕
- **H3** 周日化拍板（2026-10-12）：周锚点由"周四"改"周三"、周区间由"周一~周日"改
  "周日~周六"（R21/R32 落地）。既有开发档的 assignW 周键随之作废——impl 未发布，
  接受重置，不做键迁移。

## I · AI 规划（模块 11）

> AI 的文档、对话、运行记录**不进任务存档**；任务树仍只认《6》§A/§B 的结构。
> 本节定义 AI 模块自己的持久化契约、服务端 API 与安全边界。

### I1 · 原则

- **任务存档不新增必填字段**，schema 仍为 2；AI 不改变任务树核心结构。
- AI 的产物全部在服务端受管目录；任务写入只能经 `mutations`（E1）。
- 文档与任务**解耦**：删文档不删任务；删树不自动删文档；用 `planRun` 建立关联。
- 节点级 `docRef`（文档路径+锚点）为 ⚖️ 后续项；v1 用 `planRun.appliedNodeIds` 做批次级追溯。

### I2 · 受管目录

```
{DATA_DIR}/agent-docs/{goal-slug}/
  00-目标契约.md
  01-现状与约束.md
  02-分解结构.md
  03-任务清单.md
  04-排期与执行.md
  99-决策记录.md

{DATA_DIR}/agent-runs/{runId}.json     # 运行记录
{DATA_DIR}/agent-chats/{conversationId}.json  # 会话记录
```

- `goal-slug`：小写、短横线、去特殊字符；冲突时加 `-2`、`-3`。
- 同一目标多轮 run 可复用文件夹并递增版本，或新建 `{slug}-2/`；由用户在评审时选择。
- 目录根由服务端配置（`AGENT_DATA_DIR` 或 `DATA_DIR` 子目录），不在静态目录下暴露。

### I3 · 文档 frontmatter

```yaml
---
runId: run-20261025-001
docType: goal-contract   # goal-contract | current-state | decomposition | task-list | schedule | decision-log
order: 0
treeId: 42
goal: 6 个月内通过 CET-6
status: draft            # draft | reviewed | approved | stale
version: 3
upstream: []             # [{docType, version}]
updatedAt: 2026-10-25T10:00:00+08:00
---
```

- `status=stale` 表示上游/任务树已变化，需重新生成或确认；stale 文档不得作为落库依据。
- 文档正文的最小字段见《5》R44 与 11.3。
- 文档根路径 + `runId` 共同定位；同一 run 的文档版本在 `planRun.docVersions` 汇总。

### I4 · planRun 记录

```json
{
  "id": "run-20261025-001",
  "goal": "6 个月内通过 CET-6",
  "treeId": 42,
  "domainId": 3,
  "docRoot": "cet6",
  "status": "clarifying | drafting | review | applied | discarded | apply_failed | orphaned",
  "docVersions": { "goal-contract": 3, "task-list": 2 },
  "createdAt": 1760000000000,
  "appliedAt": 1760000000000,
  "conversationId": "chat-20261025-001",
  "appliedNodeIds": [101, 102, 103],
  "summary": {
    "createdTrees": 1, "createdNodes": 18, "updatedNodes": 4,
    "assignments": { "m": 5, "w": 9, "d": 12 },
    "completed": 0, "deleted": 0
  }
}
```

- `appliedNodeIds` 是文档→任务的批次级追溯锚点；节点删除后 id 不回收（D1），记录仍可读。
- `status=orphaned`：引用的树已删除；文档保留，任务不再存在。
- `status=apply_failed`：批量事务失败；必须整批回滚（R47/R53），记录失败原因摘要。

### I5 · 会话记录

```json
{
  "id": "chat-20261025-001",
  "runId": "run-20261025-001",
  "model": "deepseek-chat",
  "messages": [
    { "role": "user", "content": "…", "createdAt": 0 },
    { "role": "assistant", "content": "…", "toolCalls": [], "createdAt": 0 },
    { "role": "tool", "name": "get_tree", "resultSummary": "…", "createdAt": 0 }
  ],
  "createdAt": 0,
  "updatedAt": 0
}
```

- 工具原始大 payload 只存摘要；完整结果不重复入档，避免体积膨胀。
- 会话可截断/摘要；保留策略与“删除 run 是否连带删会话”见 11.7 待定。
- 会话不存 API Key、Authorization、完整系统提示中的敏感配置。

### I6 · 与任务存档的关系

- 存档根（§A）**不新增** `ai` 必填字段；如需记住上次打开的 run，用 `lxp_redesign.prefs`
  的 `agent_last_run`，不属于存档根（同 §A2）。
- 任务节点**不新增**必填字段；`docRef` 为 ⚖️ 后续项。
- 导出/导入存档（§H）不包含 AI 文档/会话；AI 工作区单独导出为后续项（I10）。
- 删除树：相关 run 标 `orphaned`，文档保留；不自动删文档（R57）。

### I7 · 服务端 API

所有接口复用现有 Bearer TOKEN 鉴权；未授权 401。

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/agent/chat` | 对话回合；SSE（token/tool_call/tool_result/done/error）或 JSON |
| GET | `/api/agent/docs/tree?runId=` | 文档树（目录/文件/状态/版本） |
| GET | `/api/agent/docs/file?path=` | 读取单篇 Markdown |
| PUT | `/api/agent/docs/file` | 写入/覆盖 `{path, content, baseVersion?}` |
| POST | `/api/agent/docs/folder` | 新建文件夹 `{path}` |
| POST | `/api/agent/docs/rename` | 重命名 `{from, to}` |
| DELETE | `/api/agent/docs/file?path=` | 删除文档（需确认） |
| GET | `/api/agent/runs` | 运行记录列表 |
| GET/PUT | `/api/agent/runs/:id` | 读取/更新运行记录 |
| GET/PUT | `/api/agent/chats/:id` | 读取/更新会话 |

- 任务数据的读写**不新增 REST 接口**：AI 的任务写入在浏览器端经 `mutations` 执行；
  服务端只负责 LLM 代理与文档/运行记录存储。
- 若未来做后台 agent，才需要服务端任务 API；届时必须解决客户端单写者与冲突，另立契约。

### I8 · 路径、原子性与版本

- `path.resolve` 后必须在 `AGENT_DOCS_ROOT` 内；拒绝绝对路径、`..`、符号链接逃逸。
- 仅允许 `.md`；单文件 ≤256KB（⚖️）、单 run ≤2MB（⚖️）、目录深度 ≤5（⚖️）。
- 写入：先写临时文件再 `rename`；失败不破坏旧文件。
- 并发：`PUT /api/agent/docs/file` 支持 `baseVersion`（mtime/hash）；冲突返回 409 +
  当前版本，由客户端提示刷新/另存新版本。
- 文件名为用户可读；不得包含路径分隔符、控制字符；冲突由服务端提示。

### I9 · 错误路径

| 情形 | 行为 |
|---|---|
| LLM 超时/断流 | 保留草稿；任务零变化；可重试（R53） |
| LLM 429/限流 | 退避一次；仍失败提示稍后重试 |
| LLM 401/Key 无效 | 提示“模型未配置/凭证失效”；不泄露 Key |
| 工具参数非法 | 返回结构化错误给模型；连续失败暂停并提示 |
| 落库批次部分失败 | 整批回滚；`planRun.status=apply_failed`；不得半写 |
| 文档写入冲突 | 409 + 当前版本；提示刷新/另存新版本 |
| 文档路径非法/非 md/超大 | 400；不写入；记录审计 |
| run 引用的树已删除 | `status=orphaned`；文档保留；提示用户 |
| 静态目录暴露 | 视为安全缺陷：必须先修静态挂载，再上线 AI 文档 |

### I10 · 备份与迁移

- §H 的备份=任务存档 JSON，不含 AI 文档/会话。
- AI 工作区导出（zip：agent-docs + agent-runs + agent-chats）为 ⚖️ 后续项；
  在此之前用户可直接从受管目录复制。
- 删除 AI 数据不影响任务存档；删除任务存档不影响 AI 文档。
- schema 仍为 2；AI 不触发任务存档迁移。

### I11 · 安全前提（上线前必须）

- 静态服务不得把 `DATA_DIR`/`AGENT_DOCS_ROOT` 暴露为可下载路径；
  当前 `express.static(WORKSPACE_ROOT)` 需改为显式挂载 `/app` 与 `/ez-tree`，并屏蔽 `/app/data`。
- 文档/聊天接口必须鉴权；不能靠“路径猜不到”当安全。
- Markdown 渲染必须禁用原始 HTML 或严格清洗（R51）；否则 token 可被 XSS 窃取。
- API Key 只在服务端环境变量（R52）；日志脱敏。
