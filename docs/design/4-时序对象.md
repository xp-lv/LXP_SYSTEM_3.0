# 4 · 时序对象

从《1-模块细分解》《2-交互矩阵》《3-交互全定义》聚类出**需要按时序设计的对象**：
行为随时间展开、顺序不可乱的东西。分五类：状态机 / 因果级联 / 动画时间线 / 真实时间 / AI 规划。

> 状态标记：〔已定义〕定义在 redesign 文档内 ·〔demo 验证〕demo 调通可抄参数 ·
> 〔旧实现〕旧 app 有实现需收编 ·〔待设计〕尚无定义

## 聚类五 · AI 规划（模块 11）

| # | 对象 | 时序（顺序不可乱） | 状态 |
|---|---|---|---|
| T24 | AI 对话回合 | 用户发送 → 上下文快照 → 模型流式回复/工具调用 → 工具结果回填 → 最终回复 → 会话落盘 | 〔待实现〕 |
| T25 | 文档链生成 | 目标契约 → 现状/约束 → 分解结构 → 任务清单 → 排期/执行；后篇引用前篇版本 | 〔待实现〕 |
| T26 | 方案评审与落库 | 预览 → 用户确认 → 全量校验 → 批量变更（一次快照）→ 派生 → 呈现 → 存档；失败回滚 | 〔待实现〕 |
| T27 | 上下文刷新 | 每回合前读取最新任务树/日历/容量；与上次快照比对，变化则提示 | 〔待实现〕 |
| T28 | 失败恢复 | 超时/限流/工具失败 → 保留草稿 → 可重试；不落库 | 〔待实现〕 |
| T29 | 执行复盘循环 | 落库 → 执行 → 读进度 → 复盘文档 → 调整建议 → 再次确认落库 | 〔待实现〕 |

> AI 的时序红线：**文档/对话先于确认，确认先于落库，校验先于写入，快照先于批量执行**；
> 任一步失败不得留下半落库。目标值（待实测）：首字 ≤3s、单回合 ≤60s、200 节点批量落库 ≤2s。

4. ~~**统一节奏表**~~ **已建**（见下表）——各时序对象现状值记录在册；
   统一为 CSS token 是后续优化，不阻塞；7 号 N6 引用本表；

   多设备同一 run 的锁策略均待拍板（见 11 号模块“待定”）。
