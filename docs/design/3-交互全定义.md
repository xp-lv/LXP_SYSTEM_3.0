# 3 · 交互全定义

《2-交互矩阵》回答"**谁和谁**有交互"（静态结构）；本文回答"**全部交互是什么**"（动态全集）：
每个用户输入的响应、每个自动行为、每次变更的传播、每类状态的迁移。
两者合起来才是系统的交互全定义。

## 3 · 数据传播链（一次写操作扇出到哪里）

```
用户操作（任意视图）
   └→ 变更服务（唯一写入口：改数据 + undo 快照）
        ├→ 派生计算（工时/进度/断梢/告警 重算）
        │    ├→ 世界树：三态更新（红光↔指线↔叶团）
        │    ├→ 信息面板：选择框%/大纲状态点/顶栏读数/悬停卡
        │    ├→ 规划页：当前视图重渲染
        │    └→ 归档判定（整树完成？→ A3）
        └→ 持久化（localStorage）
领域操作（种植/删树/领域增删改）→ 同上传播；是否入 undo 栈 ⚖️（R35）
```

AI 规划有两条**互斥**的路径：

```
AI 对话 / 生成文档
   └→ 只写服务端受管目录（agent-docs / agent-runs / agent-chats）
        └→ 不触碰任务树、不入 undo、不触发 3D 重建

用户确认「应用方案」
   └→ 批量变更事务（唯一写入口，一次快照）
        ├→ 全量校验（规则/容量/引用/tempId 解析）
        ├→ 逐项执行（建树→建节点→改名→工时→落月→周→日→完成/删除）
        ├→ 派生计算 → 树/面板/规划页更新 → 归档判定
        ├→ 持久化（localStorage + 云端推送）
        └→ 写 planRun（文档版本 + appliedNodeIds + 摘要）
   失败 → 恢复快照，整批零残留；成功 → 整批一步 undo
```

**不变量**：所有扇出都由变更链驱动，无任何模块绕过它直改数据或直刷界面；
AI 的对话与文档不构成任务写入，只有“用户确认应用”才进入变更链。

## 4 · 状态定义

### 4.1 任务呈现态（树上三态 + 待定项）
`断梢红光(未排期未完成) ⇄ 日梢指线(已排期) → 完成叶团(分叉全完成)`
（时间维度是否上树：待拍板，见 02.3 待定）

### 4.2 排期链
`无 → 落月(assignM) → 落周(assignW) → 落日(assignD) → [逾期冻结+补点(makeup)] → 完成`
改排期：未超时=直接替换；超时=原锚点冻结+makeup 覆盖。

### 4.3 视图链
`世界 ⇄ 宏观 ⇄ 周 ⇄ 日`（每层往返都有飞移动画纽带；Esc 逐层退出）

### 4.4 激活链
`领域(activeIdx) → 树(activeTreeIdx) → [星球下钻焦点]`
任何时刻两级激活必须指向有效目标，否则走回退链（A7）。

### 4.5 AI 规划状态机
```
空闲 → 澄清中 → 分析中 → 文档链草稿 → 待确认 → 已落库 → 复盘中
         │         │            │           │
         │         └→ 失败/超时 ─┴→ 重试     └→ 放弃（discarded，文档保留）
         └→ 用户取消 → 空闲
已落库 → 上游任务树/文档变化 → 相关草稿 stale → 重新分析
```
- **待确认**是任务写入的唯一前置状态；未到该状态或 `stale` 时“应用”禁用。
- 失败不改变任务数据；只影响会话/草稿。
- 已落库后再次调整 = 新一轮应用，仍走“待确认 → 批量落库”。

## 5 · 完备性口径

本文如何保证"全"：
1. **用户交互**：按视图枚举输入（指针左/右/双击/拖/悬停/滚轮 + 键盘 + 面板按钮），
   每个视图每个输入都有归宿（1.1–1.7 共 **74 条**）；
2. **自动行为**：枚举触发时机（完成/排期/启动/跨天/每帧/进出场/删除/AI 回合与落库）
   共 **15 条**；
3. **传播与状态**：写操作只有一个入口，扇出面封闭枚举；状态迁移五条链
   （呈现态/排期链/视图链/激活链/AI 规划态）；
4. 新增功能时：先在《1-模块细分解》加最小模块 → 在本表加交互行 → 在矩阵加模块对 →
   在《5》补规则 → 在《4》补时序 → 在《6》补数据契约 → 在《7》补验收。七份文档同步，
   缺一即视为定义未完成。
