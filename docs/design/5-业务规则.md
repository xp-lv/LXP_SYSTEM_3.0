# 5 · 业务规则

> 收编散落在旧文档/旧实现中的**精确规则语义**——每条规则写成一句可判定的话。
> 标注：〔已定〕旧系统验证过的语义直接沿用 · ⚖️ 新系统待定。
> 规则编号 R1…，供《7-验收标准》引用。

---

## A · 分解与级别

- **R1** 只有叶子任务可分解；分解后父任务工时由子任务汇总。〔已定〕
- **R2** 顶层画布最多 3 级（主→二级→三级），三级无「＋」。〔已定〕
- **R3** 周度分解最多两层（月度→周任务→再分一次），之后无「＋」；
  更细的属于今日清单草稿分解（不入树、不带工时）。〔已定〕
- **R4** 级别 `lvl` 由分解发生的域决定（top/month/week/temp），与树深度无关。〔已定〕

## B · 落月（宏观）

- **R5** 只有顶层叶子可拖入月卡；月卡只显示顶层任务。〔已定〕
- **R6** 一个任务只落一个月；跨月的大目标在画布分解成多个子任务分别落月。〔已定〕
- **R7** 移出该月（月卡「×」）：该任务及其子树的 月/周/日分配**全部解除**，
  任务节点保留，可重新拖入。〔已定〕
- **R8** 换月=干净重来：已落月的任务拖到另一月时，只保留它的**新 assignM**，
  其下全部月度分解子树、周分配、周日分配**整体删除**，在新月重新规划。〔已定〕
  其下已存在的补点（makeup）**随删**——补点是排期链的伴生物，链断则补点无意义。〔已定〕
- **R9** 跨月的周里落日到上月边界日，不改写月度任务的 assignM 锚点。〔已定〕

## C · 落周（宏观→微观的桥）

- **R10** 月度任务拖入周度球=落周（级联补齐 assignM）。〔已定〕
- **R11** 改排到别的周**唯一入口**是月详情的周框；周画布内不做跨周拖拽。〔已定〕

## D · 落日（微观）

- **R12** 落日前必须有工时：0h 拖入泡泡被拦（闪烁+提示）。〔已定〕
- **R13** 一个任务不落多个日；要跨日完成就先做周度分解。〔已定〕
- **R14** 落日级联补齐 assignW/assignM。〔已定〕
- **R15** 泡泡内小字条：拖出泡泡=移出落日；拖到另一泡泡=换日。〔已定〕

## E · 补点与逾期

- **R16** 逾期判定——**双轨制**〔已定〕：
  - **overdue 标志**（历史事实）：`assignD < 今天 && progress<1` → 启动/跨天扫描标记，
    不可逆（直到完成）。补点不清除 overdue。
  - **落果条件**（展示层）：`(makeup || assignD) < 今天 && progress<1` → 树下落果。
    即：有有效补点（makeup ≥ 今天）时，任务**挂枝头带「补」角标**；补点也过期才落地。
- **R17** 逾期后的重排（拖动/补点选择器）**不改写原 assignD/assignW**——
  原排期冻结为历史锚点；新排期写入 `makeup`（粒度到日）。
  `overdue` 标志在补点后**保留**（R16 历史层）；展示归属按有效日 `makeup || assignD`（R16 展示层）。〔已定〕
- **R18** makeup 可覆盖更新、可清除；清除后回到纯逾期态；补点选择器窗口=未来 14 天（满日灰显不推荐、今日高亮）。〔已定〕
- **R19** 补点兑现（完成）：按补点日落结果、落果清除；原位灵魂/逾期痕迹消散。〔已定·措辞随"时间维度/周树果态"两项拍板〕
- **R20** 对照：**未超时**任务的正常重排=直接替换（无历史锚点）。〔已定〕
- **R21** 落果=`有效日（makeup || assignD）在本周 && 有效日 < 今天 && progress<1`——
  **不要求 overdue 标志为 true**（补点过期同样落地，R16 展示层的直接推论）。
  有效补点未兑现的任务**不落地**——挂枝头带「补 MM-DD」角标。
  落叶堆=`assignD < 本周起始日 && 无有效补点 && progress<1`（历史欠账）。
  **"本周"=周日起至周六止**（非周一~周日）。
  **日/周边界=凌晨 5:00**——过了 5:00 才算进入新的一天/新的一周（夜猫子跨零点不切日）。〔已定〕
- **R58 跨周未落日欠账（R21 补充，编号延续）**：
  树任务 `progress<1`、有效日为空（`effD(n)==null`）、有效周为历史周
  （`weekDays(effW(n))[0] < 本周起始日`）、且无有效补点
  （`makeup` 为空或 `< 本周起始日`）→ 计入落叶堆。
  欠账锚点取该周起始日（周日），面板显示 `周 MM-DD`，不伪造 `assignD`。
  本周内未落日任务不提前落地；历史周未落日任务不生成落果，直接进入落叶堆。
  临时任务仅当自身显式有历史 `assignW` 时适用；无 `assignW` 的全局日程池任务不进入落叶堆。
  点击欠账仍按 R17/R18 写 `makeup` 重排；清除补点后若原周仍为历史周则回到落叶堆。〔已定〕

## F · 工时与容量

- **R22** 工时自周度域开始存在：顶层/月度不显示不编辑；父级=子级汇总。〔已定〕
- **R23** 日容量默认工作日 6h、周末 0h；点改持久化，工作日/周末分开记忆。〔已定〕
- **R24** 波浪水位=当日已排工时/容量；超容量变红提醒但**不阻止**落日。〔已定〕
- **R25** 补点任务照常计入容量。〔已定〕

## G · 临时任务

- **R26** 临时任务是日程不是规划：全局日程池、不入树、不属于任何领域、
  世界与宏观规划不可见。工时**创建时可空/0**（快速记录优先），
  落日前**必须有工时**（0h 拖入泡泡被拦，与周任务同规则 R12），
  周画布显示琥珀填工时提示。〔已定〕
- **R27** 临时任务只出现在周度树（周画布「日程」组、七日泡泡、今日清单）。〔已定〕

## H · 完成与归档

- **R28** progress 为二值（0/1）；完成判定=子任务全完成自动完成父。
  **撤销边界〔已定〕**：
  - 取消完成的入口仅一条——**今日清单点环**。
  - 撤回条件=completedAt ≥ 今天 00:00（**completedAt** 新增于《6》§B——progress→1 时写入时间戳；
    刷新/重启后仍可撤回"今天完成的"；昨天的不可撤）。
  - 历史日视角的环一律**只读**（R33 覆盖执行态）。
  - Cmd+Z 在今日虚拟树期间**维持禁用**（R36 不变——undo 栈快照针对真树，与虚拟周树互斥）。
  - 排序/临时任务操作**不走撤回**（可手动改回）。
- **R29** 树上完成=该分叉下全部任务完成 → 长叶团（骨架不变）。〔已定〕
- **R30** 整树全部叶子完成 → 自动归档：树离开世界，归档记录带**原领域 id + 整树快照**；
  恢复的树不即时再归档（再度变化并完成后才再次归档）。〔已定〕
  归档呈现=**仅存档不可见**〔已定〕——orchard 数据保留（可导出备份），无 UI 入口；归档树离场即为视觉终点。
- **R31** 删除树=未完成也不打算继续，直接删（二次确认；有未完成时加强确认），与归档区分。〔已定〕

## I · 历史周

- **R32** 周边界=**周日 05:00**（R21 同源）；过边界后上周转为历史周。〔已定〕
- **R33** 历史周只读清单：分解/落日/换日/移出/工时/容量/临时任务/删除——全部禁用；
  逾期事务由补点机制（今日页）接管。〔已定〕

## J · 撤销边界

- **R34** 入栈：任务结构（增删改/改名）、分配（落月/周/日/移出/换月）、工时、
  补点、清单排序、临时任务。〔已定〕
- **R35** 不入栈（旧语义）：种植/删树（有确认）、领域增删改。
  新系统领域操作**不入栈**〔已定〕——领域增删改名走 commit() 有 toast 即时反馈，误操作可直接再改回。
- **R36** 快照为树作用域：回放自动切回所属树；今日虚拟树期间禁用 undo/redo。〔已定〕

## K · 世界规则

- **R37** 活树位置永不因增删树而改变（坑位墓碑制，按对象/id 关联）。〔已定〕
- **R38** 同一数据永远生成同一棵树（确定性）。〔已定〕
- **R39** 全岛树总量上限 **8 棵**〔已定〕；满员时种植入口禁用+原因提示，**无其他腾位操作**——出路只有删除（R31）或等整树完成自动归档（R30）。手动归档（"收起一棵树"）在 R30 果园呈现落定之后再考虑。
- **R40** 世界视图只读——树上/岛上没有任何编辑入口。〔已定〕

## L · AI 规划

> 目标：把“靠直觉分解”升级为“先澄清、再系统拆、看文档、确认后落库”。
> AI 不是规则豁免通道；它比人更严格地受 R1–R57 全部规则约束。

- **R41 AI 不直写任务数据**：不得改任务存档的 localStorage 键、data.json、节点对象；
  一切任务写入必须经模块 7 变更服务（`mutations`）。UI 偏好键（如 `agent_last_run`）除外。〔已定〕
- **R42 未确认不落库**：AI 产出的方案在用户显式确认前不得写入任务树；
  “确认”只能由用户点击或明确指令触发，AI 不得自行确认。〔已定〕
- **R43 文档链顺序与失效**：固定顺序=目标契约 → 现状与约束 → 分解结构 → 任务清单 →
  排期与执行 → 决策记录；后篇必须引用前篇版本；上游变更使下游标记 `stale`，
  未重新确认不得落库。〔已定〕
- **R44 文档最小字段**：每篇必须有规定字段（目标/成功标准/约束/非目标/假设；
  现状/差距/资源/风险；结果域/MECE/覆盖/依赖；叶子任务/工时/验收标准；
  月周日分配/容量/里程碑/缓冲；决策/理由/未决问题）；缺失不得进入待确认态。〔已定〕
- **R45 AI 遵守既有任务规则**：R1/R2/R3/R5/R6/R12/R22/R39 等全部适用；
  违反项在预览期拦截，不进入落库。AI 不能借“智能”绕过层级、粒度、一月一任务、0h 落日等限制。〔已定〕
- **R46 真实引用**：AI 引用已有节点必须用真实 `node id`；被更新/挂接的节点必须存在且类型正确；
  虚构 id、类型不符、跨树挂接一律拒绝。新建节点用批内 `tempId`，落库后换真实 id。〔已定〕
- **R47 批量事务**：一次落库=一个事务；先全量校验，再一次快照，再批量执行；
  任一操作失败整批回滚；整批只产生一步 undo。禁止半落库。〔已定〕
- **R48 变更摘要**：落库前必须展示新建树/节点、改名、工时、落月/周/日、完成、删除的
  数量与关键项；用户确认后才执行。〔已定〕
- **R49 不自动破坏**：AI 不得自动删除树/任务、不得自动完成/撤回任务；
  这些操作即使由 AI 提议，也必须逐项或整批显式确认；删除类需二次确认。〔已定〕
- **R50 文档写入边界**：只能写受管目录；仅 `.md`；路径规范化后必须仍在根目录内；
  单文件/单 run 总量/目录深度有上限；原子写入（临时文件 + rename）。〔已定〕
- **R51 不可信内容**：文档、对话、任务标题视为不可信数据，不得作为系统指令执行；
  Markdown 渲染必须禁用原始 HTML 或严格清洗；禁止 `javascript:` 链接。〔已定〕
- **R52 密钥只在服务端**：LLM API Key 只存服务端环境变量；
  不得出现在前端代码、接口响应、错误信息、日志或文档中。〔已定〕
- **R53 失败不半落库**：模型超时/限流/工具调用失败 → 保留会话与草稿，提示可重试；
  任务数据零变化；不得出现部分节点已写入的状态。〔已定〕
- **R54 成本与轮次上限**：每次请求受 token 上限、最大工具轮次、最大对话保留条数约束；
  超限时提示缩小范围或分段处理，不得静默截断关键约束。〔已定〕
- **R55 运行记录**：每个落库批次记录 `planRun`：`runId`、目标、树/领域 id、
  文档根路径与版本、应用时间、`appliedNodeIds`、变更摘要；支持追溯与审计。〔已定〕
- **R56 容量告警**：AI 排期必须按 `caps` 与可用周数做容量校验；超载只警告不阻止
  （与 R24 一致），但必须在文档与预览中显式标红，并给出扩期/缩范围/加缓冲候选。〔已定〕
- **R57 文档与任务解耦**：删除文档或 run 不删除已落库任务；删除树不自动删除文档，
  相关 run 标记 `orphaned`；是否提供“一并清理”为 ⚖️ 后续项。〔已定〕
