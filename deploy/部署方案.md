# lxp-system · Docker 部署方案

> 本文档是部署的唯一参考源。包含 Docker 核心知识、本项目的架构设计、开发/生产工作流、升级回滚策略。

---

## 一、为什么用 Docker

| 没有 Docker | 有 Docker |
|---|---|
| 「在我电脑上能跑」→ 换台电脑要装 Node.js、配路径、拷文件 | 任何有 Docker 的机器 `docker compose up` 即运行 |
| 升级 = 直接改源码 → 正式版和开发版混在一起 | 镜像（Image）是只读快照 → 正式版和开发版天然隔离 |
| 回滚 = Git revert + 手动恢复 | 保留旧镜像 → `docker tag` 一条命令切回旧版 |
| 服务器挂了要手动重启 | `restart: unless-stopped` 自动重启 |
| 环境污染：npm 装的包全局生效 | 容器隔离：每个应用独立运行 |

**核心概念（3 个词）：**

```
镜像（Image）  = 一个只读的应用快照（类比：安装光盘）
容器（Container）= 镜像的一个运行实例（类比：从光盘启动的电脑）
卷（Volume）   = 容器外的持久化存储（类比：外接硬盘——容器删了数据还在）
```

## 二、本项目的 Docker 架构

```
┌─────────────────────────────────────────────────────────────┐
│  你的电脑 / VPS（宿主机）                                      │
│                                                               │
│  ┌─────────────────────────────────────────────────────┐     │
│  │  Docker 引擎                                         │     │
│  │                                                       │     │
│  │  ┌───────────────────────────────────────────┐       │     │
│  │  │  容器：lxp-system                          │       │     │
│  │  │                                             │       │     │
│  │  │  Node.js 22 (Alpine)                      │       │     │
│  │  │  ├── server.js（Express）                  │       │     │
│  │  │  │     端口 8080                            │       │     │
│  │  │  │     ├── / → 静态文件                     │       │     │
│  │  │  │     └── /api/data → data.json           │       │     │
│  │  │  │                                          │       │     │
│  │  │  └── [不再包含源码/测试/编辑器配置]            │       │     │
│  │  └──────────┬────────────┬────────────────────┘       │     │
│  │             │            │                             │     │
│  │  ───────────┼────────────┼─────────────────────────     │     │
│  │             ▼            ▼                             │     │
│  │  Volume: lxp-data   Volume: lxp-backup                │     │
│  │  (data.json)        (每日备份)                          │     │
│  └─────────────────────────────────────────────────────     │     │
│                                                              │
│  端口映射：宿主机 8080 → 容器 8080                             │
│  浏览器访问：http://localhost:8080/app/                       │
└─────────────────────────────────────────────────────────────┘
```

### 关键设计决策

| 决策 | 理由 |
|---|---|
| **多阶段构建** | 阶段 1 装依赖+跑测试；阶段 2 只拷运行文件 → 最终镜像 ~80MB（不是 ~250MB） |
| **node:22-alpine** | Alpine Linux 只有 5MB 底座，比完整 Ubuntu 小 20 倍 |
| **非 root 运行** | 安全最佳实践，容器被攻破也不会获得宿主机 root 权限 |
| **Volume 持久化数据** | `docker compose down` 删容器，`data.json` 保留在 Volume 里 |
| **HEALTHCHECK** | 每 30 秒自检，失败 3 次自动标记 unhealthy 并重启 |
| **日志轮转** | `max-size: 10m, max-file: 3` 防止日志吃满磁盘 |

## 三、多阶段构建详解（Dockerfile）

```
阶段 1：builder                          阶段 2：runtime
┌─────────────────────────┐            ┌─────────────────────────┐
│ FROM node:22-alpine     │            │ FROM node:22-alpine     │
│                         │            │                         │
│ COPY package.json       │  只拷产物   │ COPY --from=builder     │
│ RUN npm ci              │  ───────→  │   node_modules/         │
│                         │            │   src/                  │
│ COPY app/ ...           │            │   vendor/               │
│ COPY ez-tree/ ...       │            │   index.html            │
│                         │            │   server.js             │
│ RUN node tests/run.mjs  │            │                         │
│     ↑ 测试不通过=构建失败│            │ USER app（非 root）      │
│                         │            │ CMD ["node","server.js"]│
│                         │            │                         │
│ 体积：~250MB（含npm缓存） │            │ 体积：~80MB（纯净）       │
└─────────────────────────┘            └─────────────────────────┘
```

**为什么先 COPY package.json 再 COPY 源码？**

Docker 每条指令是一层缓存。如果 `package.json` 没变，`npm ci` 这层直接用缓存（秒过）。如果源码变了但依赖没变，也不用重新下载依赖。这把构建时间从 ~2 分钟缩短到 ~5 秒。

## 四、开发 vs 生产：两套互不干扰

这是 Docker 解决你「调试时影响正式版」痛点的核心机制——**不仅代码隔离，数据也完全隔离**：

### 4.1 代码隔离（镜像层）

```
你的文件系统：
  app/src/today.js          ← 随便改，不影响任何容器
  deploy/Dockerfile          ← 构建配置

Docker 里的镜像（只读快照）：
  lxp-system:v1              ← 正式版 v1（从某个 Git commit 构建）
  lxp-system:v2              ← 正式版 v2（最新发布）
  lxp-system:latest          ← 符号链接 → v2
```

### 4.2 数据隔离（Volume 层）

```
┌─────────────────────────────────────────────────────┐
│  正式环境（docker-compose.yml，端口 8080）              │
│                                                       │
│  Volume: lxp-data → /app/data/                       │
│  └── data.json ← 你的真实任务数据                      │
│                                                       │
│  数据来源：手机/其他电脑的操作                           │
│  数据路径：宿主机 Docker 管理（容器删了数据保留）          │
└─────────────────────────────────────────────────────┘
         │ 完全隔离，互不影响
         ▼
┌─────────────────────────────────────────────────────┐
│  开发环境（docker-compose.dev.yml，端口 8081）          │
│                                                       │
│  Volume: dev-data → /app/data/                       │
│  └── data.json ← 你的测试/调试数据（随便折腾）           │
│                                                       │
│  数据来源：你在 8081 端口上的操作                       │
│  数据路径：宿主机 Docker 管理（与正式数据物理分离）        │
└─────────────────────────────────────────────────────┘
```

**你调试时用的数据和手机上用的数据是两份完全独立的文件。** 清空开发数据、加假任务、删东西随便试——正式版毫发无伤。

### 4.3 数据路径说明

`server.js` 通过环境变量 `DATA_DIR` 决定数据目录：

| 环境 | DATA_DIR | 实际路径 | 对应 Volume |
|---|---|---|---|
| Docker 正式 | 默认 `/app/data` | `/app/data/data.json` | `lxp-data` |
| Docker 开发 | 默认 `/app/data` | `/app/data/data.json` | `dev-data` |
| 本地无 Docker | 默认 `./data` | `app/data/data.json` | 无（直接写磁盘） |

### 4.4 完整数据流

```
手机浏览器勾选任务
  → HTTPS → Express API (PUT /api/data)
    → 容器内 /app/data/data.json
      → Docker Volume: lxp-data（宿主机磁盘）

你电脑调试勾选任务
  → HTTP → localhost:8081 Express API (PUT /api/data)
    → 容器内 /app/data/data.json
      → Docker Volume: dev-data（宿主机磁盘，另一块区域）
```

### 工作流

```bash
# ═══ 日常开发（不影响正式版） ═══
vim app/src/today.js
docker compose -f deploy/docker-compose.dev.yml up
# → 打开 http://localhost:8081 调试
# → 正式版 http://localhost:8080 完全不受影响

# ═══ 发布新版本 ═══
git add -A && git commit -m "v3: 新功能"
docker build -t lxp-system:v3 -f deploy/Dockerfile .
docker tag lxp-system:v3 lxp-system:latest
docker compose -f deploy/docker-compose.yml up -d
# → 正式版切换到 v3，旧版 v2 镜像保留（可随时回滚）

# ═══ 回滚 ═══
docker tag lxp-system:v2 lxp-system:latest
docker compose -f deploy/docker-compose.yml up -d
# → 3 秒切回 v2
```

## 五、数据持久化（Volume）

**最关键的一点：容器是可抛弃的，数据不是。**

```
Volume: lxp-data
  └── /app/data/data.json     ← 所有任务数据

生命周期：
  docker compose up       → 容器启动，Volume 挂载
  docker compose down     → 容器删除，Volume 保留 ✅
  docker compose down -v  → 容器+Volume 都删 ⚠️（慎用！）
  docker volume rm lxp-data → 手动删 Volume（数据全丢！）
```

### 数据流向

```
浏览器勾选任务
  → Express API (PUT /api/data)
    → 容器内 /app/data/data.json
      → 实际存储在宿主机 Docker Volume: lxp-data
        → docker volume inspect lxp-data 可以看到实际路径
```

### 备份

```bash
# 手动备份
docker exec lxp-system cat /app/data/data.json > backup-$(date +%Y%m%d).json

# 恢复
docker exec -i lxp-system sh -c 'cat > /app/data/data.json' < backup-20261013.json
```

## 六、常用命令速查

### 镜像操作

| 命令 | 说明 |
|---|---|
| `docker build -t lxp-system:v3 .` | 从当前代码构建 v3 镜像 |
| `docker images` | 列出所有镜像 |
| `docker rmi lxp-system:v1` | 删除 v1 镜像 |
| `docker tag lxp-system:v2 lxp-system:latest` | 把 v2 标记为最新 |

### 容器操作

| 命令 | 说明 |
|---|---|
| `docker compose up -d` | 后台启动 |
| `docker compose down` | 停止并删除容器（数据保留） |
| `docker compose logs -f` | 实时查看日志 |
| `docker compose restart` | 重启容器 |
| `docker compose ps` | 查看运行状态 |
| `docker exec -it lxp-system sh` | 进入容器终端 |

### 数据操作

| 命令 | 说明 |
|---|---|
| `docker volume ls` | 列出所有卷 |
| `docker volume inspect lxp-data` | 查看卷的实际路径 |
| `docker exec lxp-system cat /app/data/data.json` | 查看数据内容 |

### 清理

| 命令 | 说明 |
|---|---|
| `docker system prune` | 清理所有未使用的镜像/容器/网络 |
| `docker system prune -a` | 同上 + 删除所有未运行容器的镜像（慎用） |

## 七、部署到 VPS（公网）

### 1. 准备 VPS

```bash
# SSH 到 VPS
ssh root@你的VPS-IP

# 安装 Docker（Ubuntu/Debian）
curl -fsSL https://get.docker.com | sh

# 验证
docker --version
```

### 2. 上传代码

```bash
# 方法 A：Git（推荐）
git clone https://github.com/你的用户名/lxp-system.git
cd lxp-system

# 方法 B：SCP（无 Git 时）
scp -r ./lxp-system root@VPS-IP:/opt/
```

### 3. 启动

```bash
cd lxp-system/deploy
echo "TOKEN=你的强密码" > .env
docker compose up -d

# 验证
curl http://localhost:8080/api/health
```

### 4. 配置域名 + HTTPS（推荐 Caddy）

```bash
# 安装 Caddy（自动申请 Let's Encrypt 证书）
apt install caddy

# 配置反代
cat > /etc/caddy/Caddyfile << EOF
你的域名.com {
    reverse_proxy localhost:8080
}
EOF

systemctl restart caddy

# 现在 https://你的域名.com 可访问，自动 HTTPS
```

### 5. 防火墙

```bash
ufw allow 80    # HTTP
ufw allow 443   # HTTPS
ufw allow 22    # SSH
ufw enable
```

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐

│              │     │              │     │              │

└──────────────┘     └──────────────┘     └──────────────┘
                            │                      │
                            ▼                      ▼
                     lxp-system:v3           lxp-system:v3
                     (新镜像)                 :latest → v3
                                                 │
                                                 ▼
                                         ┌──────────────┐
                                         │  发现bug？    │
                                         │              │
                                         │  docker tag  │
                                         │  v2→latest   │
                                         │  compose up  │
                                         │  → 3秒回滚   │
                                         └──────────────┘
```

### 版本管理策略

```bash
# 每次 Git tag 对应一个 Docker 镜像版本
git tag v1.0.0
docker build -t lxp-system:v1.0.0 -f deploy/Dockerfile .

# 发布
docker tag lxp-system:v1.0.0 lxp-system:latest
docker compose up -d

# 列出所有版本
docker images | grep lxp-system
# → lxp-system  v1.0.0  ...
# → lxp-system  v0.9.0  ...
# → lxp-system  latest  ... (= v1.0.0)

# 回滚到任意版本
docker tag lxp-system:v0.9.0 lxp-system:latest
docker compose up -d
```

## 十、常见问题

**Q: 容器里的代码和我本地的代码是同一份吗？**
A: 不是。构建时 `COPY` 把当时的代码复制进镜像，之后镜像就是只读的。你改本地代码不影响运行中的容器。

**Q: 为什么 `docker compose down` 后数据还在？**
A: `data.json` 存在 Volume 里，Volume 的生命周期独立于容器。只有 `down -v` 才会删 Volume。

**Q: 怎么看容器里的日志？**
A: `docker compose logs -f` 实时查看。Express 的 `console.log` 会输出到这里。

**Q: 开发时不想每次都 build 镜像怎么办？**
A: 用 `docker-compose.dev.yml`，配置 `volumes: - ../app/src:/app/src` 把本地源码挂载进容器，改完刷新浏览器即生效（和现在不用 Docker 时一样）。

**Q: 镜像越来越大怎么办？**
A: 定期清理旧版本：`docker images | grep lxp-system | awk '{print $3}' | tail -n +5 | xargs docker rmi`（保留最近 4 个版本）。
